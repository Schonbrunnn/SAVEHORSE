# 《宝马之路》角色资源规范

本规范描述当前工程的实际接入方式。所有资源路径均相对于项目根目录；生成目标与原始提示词不等同于已达成的画面效果。人物生成历史见 `docs/人物生成素材清单.md`，Boss 生成历史见 `docs/Boss生成记录.md`。

## 交付契约

- A、B、C、D 各提供 8 个独立文件的动作 PNG，每个文件为 512×512 RGBA；“独立文件”不表示每个状态都有独立重绘的姿态。
- 每个角色另提供一张 2048×1024 RGBA 的 4×2 atlas，顺序从左到右、先上排后下排。共计 32 个动作文件、4 张动作 atlas。
- 动作文件位于 `public/game/assets/atlases/<角色ID>/<状态>.png`，atlas 位于 `public/game/assets/atlases/<角色ID>-actions-4x2.png`，布局清单位于 `public/game/assets/atlases/atlas.json`。
- 当前战斗图片加载独立 PNG，不再使用 `setCrop` 在运行时从整图切取角色、小兵或特效。透明背景必须编码为 Alpha，不能把绘制出来的灰白棋盘格当作透明。

| 角色 | 角色 ID | 上排 4 个状态 | 下排 4 个状态 | 当前姿态来源 |
|---|---|---|---|---|
| A 奇瑞队长 | `player-a` | idle / run / jump / attack | skill / guard / dodge / hurt | 面部较稳定的四个原姿态映射为八状态，结合 Tween 和位移、倾斜表现动作 |
| B 上海交通骑士 | `player-b` | idle / run / jump / attack | skill / guard / dodge / hurt | 八动作源图，人与车辆作为一个整体 |
| C 秦岭杀人兔 | `boss-c` | idle / run / jump / attack | skill / gun / fire / hurt | 八动作源图，刀与枪状态分别接入 |
| D 草莓熊博士 | `boss-d` | idle / charge / summon / lanes | fan / laser / overload / hurt | 固定机甲采用同一 idle 基底叠加不同程序特效，hurt 使用独立受击姿态 |

## 支持资源

除四套角色动作外，同一构建脚本还输出两套支持资源，供游戏按单图加载：

| 支持资源 | 独立文件目录 | 文件与 atlas |
|---|---|---|
| 三类小兵 | `public/game/assets/atlases/minions/` | shield / ranged / heavy 各有 idle、run、attack，共 9 个 512×512 RGBA 文件；`public/game/assets/atlases/minions-actions-3x3.png` 为 1536×1536 的 3×3 图集 |
| 战斗特效 | `public/game/assets/atlases/effects/` | shield / charge / slash / bullet / berry / fan / laser，共 7 个 512×512 RGBA 文件；`public/game/assets/atlases/effects-actions-4x2.png` 为 2048×1024 的 4×2 图集，最后一格留空 |

小兵文件以 `<类型>-<动作>.png` 命名，特效文件以 `<特效>.png` 命名。两套支持资源连同四套角色动作写入 `public/game/assets/atlases/atlas.json`，总计六套图集、48 个独立动作/特效 PNG。

## 姿态与身份一致性

A 当前使用 `public/game/assets/actions/player-a-4-actions-green.png`，而非八动作候选图。四个来源依次为待机、跑步、盾击、飞盾，八状态映射为 `[0, 1, 1, 2, 3, 0, 1, 0]`：jump/dodge 复用跑步，guard/hurt 复用待机；运行时通过跳跃位移、倾斜、透明度、Tween 和受击反馈区分。该选择优先保留较稳定的脸与装备，不应描述为八个独立重绘姿态。

B 使用 `public/game/assets/actions/player-b-8-actions.png`；C 使用 `public/game/assets/generated/boss-c-actions.png`。两者各接入八个动作姿态，仍需检查眼镜、发型、脸型、服装、武器和车辆等身份锚点。生成图只能以目视一致性评估，不承诺每张脸与原照 100% 相同。

C 在切枪后的移动、腾空和受击使用持枪基底配合颠簸、倾斜与闪白，不会重新切回持刀动作图。

D 使用 `public/game/assets/generated/boss-d-actions.png` 提取 idle 和 hurt。其余六个状态在同一 idle 机甲与驾驶员基底上程序绘制蓄力环、召唤门、三线弹、五发扇形弹、激光蓄能和过载电弧，以避免原生成特效中的烘焙棋盘格和跨格相连。hurt 保留不同的受击姿态。D 是固定在场地右侧的机甲 Boss，charge 是蓄力提示，不表示本体全场冲刺。场地中的伤害弹、召唤物、危险带和大激光由游戏逻辑独立生成，动作图中的特效负责提示状态。

D 的目标是实际可见机甲轮廓高度占 720 逻辑像素战场约 1/2～2/3（约 360～480 像素），不能仅凭包含透明留白的图片框高度判断。`game-src/Visuals.js` 的 D 图片框目标高度当前为 600；每次替换素材都应按 Alpha 主体范围和游戏截图复核可见尺寸。

## Portrait 与动作分离

Portrait 使用 `public/game/assets/portraits/<角色ID>.png`，为独立 1024×1280 RGBA 文件；商人另有 `public/game/assets/portraits/merchant.png`。标题、选择与剧情界面使用 portrait，战斗使用动作 PNG。两类文件拥有独立的尺寸和裁切规则，不允许把人物海报整张塞进战斗帧。

独立交付不表示所有 portrait 都是独立生成：构建优先使用 `public/game/assets/portrait-sources/` 下的专用来源，缺少来源时按脚本规定使用角色原图或动作图；C 当前 portrait 来源为其 idle 动作。调整头像来源不应覆盖动作源图。

## 构建与核验

在项目根目录执行：

```sh
pnpm assets:build
pnpm game:build
```

`scripts/build-character-assets.mjs` 负责色键转 Alpha、残留棋盘纹理的局部处理、动作分割、统一留白、D 程序特效合成、独立 PNG 与 atlas 输出、portrait 输出。`pnpm game:build` 已包含一次 `pnpm assets:build`，并重新构建浏览器游戏脚本。

核验应覆盖：四角色各八文件与状态顺序、小兵九文件、特效七文件、512×512 单图和对应图集尺寸、真实 Alpha、完整身体与装备、无邻格残片、无文字标签、portrait 与动作的加载分离；再在实际游戏中检查动作切换、脚底对齐、透明边缘、脸部可辨认程度和 D 的可见占屏比例。构建成功只证明资产流程和打包可执行，不能代替画面检查。
